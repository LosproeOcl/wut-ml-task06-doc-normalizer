# PPT 屏幕四角回归实验（首轮）

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-27 |
| 数据 | 训练集人工四角标签 236 条中的 PPT 样本；按 `doc_page_id` 分组切分 |
| 模型 | MobileNetV3-Small，输入 224×224，输出 8 维归一化四角坐标 |
| 产物 | `runs/quad-ppt-01/quad_ppt.pt`、`metrics.json`、`eval_vs_detector.json` |
| 说明 | 本报告为 83/20 首轮实验；当前分载体模型与端到端结论见 `reports/quad_localization.md` |

## 1. 目的

人工四角标注此前主要用于自动检测失败时的训练回退（ADR-0015）。本实验直接用这些标签训练四角回归器，验证两点：

1. 人工标签是否足以学习 PPT 幕布四角；
2. 学习四角能否替代或补充现有 OpenCV 检测。

## 2. 数据与训练

- 只使用清单标签以 `ppt_` 开头、落在训练集、且存在人工四角的样本；
- 按 `doc_page_id` 分组后随机 80/20 切分，避免同一张幻灯片跨集合；
- 训练 83 张，验证 20 张；
- 损失 `SmoothL1`，前 3 轮冻结主干，之后全模型微调，早停耐心 6；
- 输出顺序与标注一致：左上、右上、右下、左下。

训练在第 25 轮取得最佳验证 L2，随后早停。

| 指标 | 数值 |
|---|---:|
| 最佳验证归一化 L2 | **0.1382** |
| 验证样本数 | 20 |

归一化 L2 按整幅图的宽、高分别归一化后计算 8 个坐标的欧氏距离；0.1382 约等于每个角平均偏离 5% 画面尺寸。

## 3. 与 OpenCV 检测对比

`scripts/eval_ppt_quad.py` 在同一 20 张验证样本上运行网页同款 `detect_document`：

| 方法 | 成功数 | 平均归一化 L2 |
|---|---:|---:|
| 学习四角 | 20/20 | 0.1382 |
| OpenCV 检测（成功样本） | 18/20 | **0.1087** |

- OpenCV 在成功检出的 18 张上更准，暂不替换现有拉正链路；
- 检测失败的 2 张（`IMG_6105`、`IMG_6072`）上，学习四角的 L2 分别约 0.100 与 0.120，可作为“检测失败兜底”的候选；
- 兜底接入需要先判定载体并做几何合法性检查（凸四边形、面积比例），本次未改网页主链路。

## 4. 复现

```bash
docker run --rm -v "$PWD:/app" -w /app -e PYTHONPATH=/app/src:/app \
  docnorm:cpu-arm64 python scripts/train_ppt_quad.py

docker run --rm -v "$PWD:/app" -w /app -e PYTHONPATH=/app/src:/app \
  docnorm:cpu-arm64 python scripts/eval_ppt_quad.py
```
