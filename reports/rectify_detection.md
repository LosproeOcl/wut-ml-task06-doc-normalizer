| 样本 | 四类各 40 张，共 160 张，长边缩放至 1280 |

## 1. 实测结果

| 类别 | 检出 | 比例 |
|---|---|---:|
| 投影幕布·文字 | 35 / 40 | 88% |
| 投影幕布·公式 | 38 / 40 | 95% |
| 纸质或板书·文字 | 34 / 40 | 85% |
| 纸质或板书·公式 | 25 / 40 | 62% |
| 合计 | 132 / 160 | 82% |

检出方式分布：亮度分割四边形 84 次，边缘四边形 44 次，最小外接矩形 4 次。单图中位耗时 9.8 ms，长边 1280。

## 2. 失败类型

对失败样本与低置信样本做人工查看，原因归为四类。

1. **同一画面存在多个文档。** 投影幕布与旁边的黑板同时出现，两者并集被当成一个四边形。该情况不满足“一张照片一个文档页”的采集要求。
2. **文档超出画面。** 近距离拍摄的笔记或纸张，四角被裁切，画面中只剩局部边界。
3. **边框被分割。** 黑板由金属框分为多个面板，外框与面板边线互相干扰。
4. **边界对比度低。** 白纸放在浅色桌面，或幕布与墙面亮度接近，边界不足以通过置信门槛。

## 3. 可视化抽查

抽查覆盖边缘、区域四边形、最小外接矩形三种路径，共 12 张。

- 纸张类样本的四边形基本贴合纸张边缘，可直接用于矫正。
- 幕布类样本在“黑板加幕布”同框时，四边形覆盖两者的并集；矫正后仍包含目标页面，但引入无关区域。
- 最小外接矩形路径存在少量偏移，需要人工确认。

## 4. 决策

1. 保留当前多策略检测与置信门槛。理由：低于门槛时返回失败，比返回错误四边形更安全。
2. 未检出或低置信样本在网页中拖拽四角完成本次矫正。调整结果只服务当前会话，不写入数据集，也不作为评估金标准。
3. 项目目标 G-04 由“自动检出率 90%”调整为“自动检出率 80%，其余交互调整或跳过”。90% 作为后续优化目标保留，不在两周工期内承诺。
4. 后续优化方向依次为：在“多文档同框”样本上增加目标选择规则；以独立模型生成参考角点并量化一致性；必要时以 DocAligner 作为对照方案。

## 5. 复现方式

```bash
docker run --rm -v "$PWD:/app:ro" -w /app docnorm:cpu-arm64 \
  python -m pytest tests/unit/test_rectify.py -q -p no:cacheprovider
```

检测率统计脚本未纳入仓库，原因是它依赖完整样本目录。复现时按类别各取 40 张，调用 `detect_document`，统计返回值非空的样本数。


## 6. 2026-11-27 人工四角参数调优

用 338 张训练集人工四角（不含验证/测试）对 OpenCV 检测器的 Canny 阈值与面积门槛做网格搜索，按 `doc_page_id` 分组切分。OpenCV 检测器本身没有可训练权重，这一节训练的是它的规则参数。

| 载体 | 训练/验证 | 参数 | 验证检出率 | 成功样本 L2 |
|---|---|---:|---:|---:|
| PPT | 153 / 52 | 50 / 150（默认） | 76.92% | 0.1885 |
| PPT | 153 / 52 | **90 / 250** | **84.62%** | **0.1827** |
| 纸质 | 104 / 29 | **50 / 150（默认）** | 75.86% | 0.1445 |
| 纸质 | 104 / 29 | 30 / 90 | 86.21% | 0.1679 |

- 面积门槛 0.05–0.20 与 0.98/0.99 对结果无影响，失败主要发生在候选生成阶段。
- PPT 90/250 检出率更高，但用该参数重训分类器仅 85.71% / F1 81.52%，低于当前 95.24% / 92.93%；最终分类拉正回退 50/150，90/250 仅保留检测实验。纸质保留 50/150。全链路验证集维持 86.27% / 宏 F1 86.19%，PPT 分支 95.24%。
- 纸质改用 30/90 虽提高检出率，但全链路验证集降到 84.31%，因此不采用。逐样本核对：门控在 51 张验证集上 51/51 全对，下降不是载体误判；唯一翻转样本是 `formula_14`——默认参数未检出，保留原图分类为 formula（正确）；30/90 检出一个面积占比 0.61 的四边形，拉正后 paper 集成判为 text（错误）。这说明“检出率更高”不等于“定位更准”，错误检出比安全弃检更伤下游，后续需要给检测结果加质量门槛，或改用学习四角模型。
- 参数写入 `configs/default.yaml` 的 `ppt_canny_low/high`、`paper_canny_low/high`，由 `web/services.py` 在门控判定载体后选择。
- 复现：`python scripts/tune_rectify_detector.py --carrier ppt` / `--carrier paper`。
