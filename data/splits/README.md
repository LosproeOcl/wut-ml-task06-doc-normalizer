# 数据划分目录说明

本目录存放数据集划分文件。划分文件纳入版本控制，以保证所有组员与所有实验使用同一划分。

## 文件命名

```text
split_v1.json
split_v2.json
```

版本号递增。已冻结的划分文件不得修改。确需调整时创建新版本，并重跑全部实验。

当前有效版本为 `split_v2.json`，2026-11-26 冻结，计数为训练 240、验证 51、测试 53，合格样本 344。`split_v1.json` 仅保留作历史记录，不得用于训练或评估。v2 的变更原因为：样本 `IMG_6111` 文件缺失，经排除表新增 `missing_file` 后，移除其所属分组 `PT-012`，其余分组归属与 v1 一致。

## 划分规则

1. 分组键为 `doc_page_id`。同一文档页的全部样本只进入一个集合。
2. 比例为训练集 70%、验证集 15%、测试集 15%。
3. 按内容类别（文字/公式）与拍摄者分层，使分布接近；载体分布作为检查项，不强制均衡。
4. 随机种子固定为 42。
5. 测试集须包含至少两名非主要拍摄者的样本。
6. 已排除样本不得保留在划分中。数据层须校验清单文件的实际存在性，缺失文件按排除处理并重建版本。

## 文件结构

```json
{
  "version": "v2",
  "seed": 42,
  "group_key": "doc_page_id",
  "ratio": {"train": 0.7, "val": 0.15, "test": 0.15},
  "groups": {"train": [], "val": [], "test": []},
  "counts": {"train": 0, "val": 0, "test": 0},
  "frozen_at": "YYYY-MM-DD",
  "manifest_sha256": "清单文件哈希"
}
```

`manifest_sha256` 用于校验划分与清单是否对应，口径为清单文件原始字节的 SHA-256（`hashlib.sha256(path.read_bytes())`，不做换行或编码转换）。两者不一致时评估脚本须终止执行。注意：仓库 `.gitattributes` 可能在检出时转换换行导致哈希变化，跨平台核验须以字节级一致为准。

## 冻结流程

1. 数据负责人执行划分脚本。
2. 检查三类样本的类别分布与拍摄者分布。
3. 由评估负责人复核。
4. 填写 `frozen_at` 与 `manifest_sha256`，提交至仓库并告知全组。
