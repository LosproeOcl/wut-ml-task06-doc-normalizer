# 空间偏度优化调研

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-27 |
| 问题 | 正面 PPT/幕布识别较准，存在空间偏度的图像不及预期 |
| 约束 | 暂不新增样本；只用现有自采验证集与合成偏度压力测试 |
| 结论 | 主要瓶颈在载体门控，不在内容模型；门控 TTA + 阈值可显著改善，但需真实偏度样本复核 |
| 相关图 | `reports/figures/spatial_skew_accuracy.png`、`spatial_skew_gate.png`、`spatial_skew_examples.png` |

## 1. 问题表现

`docs/record-img/` 中新增了三张过程截图：

- `测试识别 PPT-text1-正面.png`、`测试识别 PPT-text2-正面.png`：正面样张；
- `测试识别 PPT-text3-偏度-不达预期.png`：偏度样张，四角框与矫正/扫描结果仍保留明显倾斜或屏幕边框。

这些截图说明问题不只出现在内容分类，也可能出现在四角定位、载体门控与扫描件生成环节。截图中人物已做像素化脱敏。

## 2. 现有链路

```text
原图 → 载体门控（PPT/幕布 vs A4 纸质稿）
      ├─ PPT   → exp-cnn-05 内容模型
      ├─ paper → 纸质稿 CNN 集成
      └─ 模型缺失 → SVM 兜底
```

偏度可能影响三个环节：

1. 载体门控把倾斜幕布判成纸质稿，走错分支；
2. 自动四角检测失败或框到屏幕外框，拉正后仍残留透视；
3. 内容模型对残余偏度不鲁棒。

## 3. 无新增样本的实验设计

自采验证集只有 21 张 PPT 页，且 `angle_deg` 大多为 10°，缺少大角度真实样本。因此用**合成梯形透视**做压力测试：

- 对 21 张 PPT 验证页分别施加 0°/10°/20°/30°/40° 梯形透视；
- 交替使用上下边/左右边收敛，模拟不同方向的相机倾斜；
- 不参与训练，仅用于评估；
- 同时评估“内容模型”和“完整链路”两条路径。

脚本：`scripts/eval_spatial_skew.py`、`scripts/eval_gate_skew.py`。

## 4. 结果

### 4.1 内容模型与完整链路

| 合成偏度 | 内容模型（拉正后加偏度） | 完整链路（原门控 0.5） |
|---:|---:|---:|
| 0° | 95.2% | 95.2% |
| 10° | 90.5% | 95.2% |
| 20° | 90.5% | 90.5% |
| 30° | 90.5% | **76.2%** |
| 40° | 85.7% | **76.2%** |

内容模型在 30°/40° 仍有 90.5%/85.7%，而完整链路掉到 76.2%。说明主要损失来自门控/路由，而不是内容模型本身。

### 4.2 门控 PPT 召回

| 合成偏度 | 原门控 @0.5 | 原门控 TTA @0.3 | 偏度增广门控 TTA @0.2 |
|---:|---:|---:|---:|
| 0° | 100% | 100% | 100% |
| 10° | 95.2% | 100% | 100% |
| 20° | 100% | 100% | 100% |
| 30° | 76.2% | 90.5% | 90.5% |
| 40° | 38.1% | 61.9% | **76.2%** |

纸质稿召回在所有阈值/角度下保持 100%，说明在当前验证集上降低阈值没有引入纸质误判。偏度越大，门控越倾向把 PPT 判成纸质稿。

### 4.3 门控 TTA + 阈值 0.3 的完整链路

| 合成偏度 | 原链路 | 门控 TTA + 0.3 |
|---:|---:|---:|
| 0° | 95.2% | 95.2% |
| 10° | 95.2% | 90.5% |
| 20° | 90.5% | 90.5% |
| 30° | 76.2% | **85.7%** |
| 40° | 76.2% | **85.7%** |

五个角度的平均准确率从 **86.7%** 提升到 **89.5%**（+2.9 个百分点）。代价是 10° 时有一张样张被强制走 PPT 分支，失去纸质分支的纠错；30°/40° 各多对 2 张。

### 4.4 其他尝试

- **内容模型旋转 TTA**：30° 从 90.5% 提升到 95.2%，40° 无变化；完整链路仍受门控限制。
- **偏度增广门控**：`carrier-gate-skew-01` 外部验证 100%，30°/40° 门控 PPT 召回提升到 90.5%/76.2%；完整链路与“原门控 + TTA + 0.3”相同（85.7%），暂未显示额外收益。
- **内容模型偏度增广**：`exp-cnn-skew-01` 在原始验证集只有 70.6%（对照 80.4%），40° 合成偏度 76.2%（对照 85.7%），**不采用**。强透视增强明显伤害正常样本。

## 5. 判断

1. **内容模型不是主要短板**：残余偏度下仍有 85%–90%；当前 webapp 的明显下降主要来自门控误路由。
2. **门控阈值/TTA 是成本最低的无样本优化**：0.3 阈值 + 旋转 TTA 在合成偏度下把 30°/40° 从 76.2% 提到 85.7%，纸质召回未降。
3. **偏度增广门控可作为候选**：对 40° 门控召回更好，但完整链路尚未超过阈值/TTA 方案，需真实样本验证。
4. **内容强增广不可取**：正常验证集掉 10 个百分点，说明不能用合成强透视替代真实偏度数据。
5. **四角/扫描件仍需改进**：截图显示偏度样张的扫描件仍带屏幕边框或残余倾斜；screen bbox 是轴对齐矩形，不能解决透视，需边缘/消失点或更稳的四角检测。

## 6. 建议

### 短期（不新增样本）

- 增加可选配置：`gate_tta=true`、`gate_threshold=0.3`，仅在“门控不确定”或检测到明显偏度时启用；默认仍保持 0.5 + 无 TTA。
- 对门控输出做温度/阈值校准，先在小验证集上检查纸质误判。
- 保留 `carrier-gate-skew-01` 作为候选，不要直接替换主链路。
- 不从合成偏度训练内容模型；当前证据为负。

### 待真实偏度样本到位后

1. 按 `angle_deg` 分桶（10° 以下 / 10–20° / 20–30° / 30° 以上）报告门控与内容准确率；
2. 在真实样本上复测 0.3/0.4/0.5 阈值与 TTA；
3. 对比“原门控”和“偏度增广门控”，以完整链路准确率为准；
4. 单独评估四角检测成功率与扫描件质量，不要只看分类标签；
5. 测试集保持冻结，不用偏度样本反复调参。

```bash

  docnorm:cpu-arm64 python scripts/eval_spatial_skew.py \
  --out reports/spatial_skew.json

# 门控阈值/TTA
docker run --rm -v "$PWD:/app" -w /app -e PYTHONPATH=/app/src:/app \
  docnorm:cpu-arm64 python scripts/eval_gate_skew.py

  docnorm:cpu-arm64 python scripts/train_screen_gate.py \

  --epochs 3 --input-size 160 --batch-size 48 --skew-augment
```

## 8. 边界

- 合成梯形透视是压力测试，不等于真实投影幕布的光照、反光、屏幕边框与拍摄距离；
- 验证集只有 21 张 PPT 页，单张影响约 4.8 个百分点；
- 测试集未参与；
- 本调研未把 0.3 阈值/TTA 设为默认，也未替换主链路模型；
- 真实偏度样本到位后需重新评估，不能仅凭本报告上线；
- **数据一致性提醒**：调研时 `check_dataset.py` 报告 11 个清单路径缺失、11 个未登记文件，多为样本在 `01_ppt_text` / `02_ppt_formula` 等目录间移动（例如 `IMG_6174` 清单写 `01_ppt_text`，实际在 `02_ppt_formula`）。空间偏度评估脚本按文件名回退读取，仅用于分析；训练脚本没有启用该回退。正式训练/评估前应先修正清单与目录，避免文件与标签错位。
