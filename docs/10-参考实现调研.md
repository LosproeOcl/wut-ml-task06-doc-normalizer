## 1. 调研范围与方法

检索平台为 GitHub，检索词包括 image redaction privacy、face blur anonymize、document pii redaction 与 qr code privacy。筛选标准有四项。

1. 能够离线运行，不依赖云端接口。
2. 提供图像级处理，而非仅处理纯文本。
3. 许可证允许参考或复用。
4. 技术栈与本项目的 Python 与 OpenCV 方案兼容。

共筛选出七个项目。其中三个可直接复用组件，四个仅作设计参考。

## 3. 逐项分析

### 3.1 microsoft/presidio

该项目是个人信息检测与遮盖的通用框架，包含文本、图像与结构化数据三个方向。图像模块 presidio-image-redactor 的处理流程为：先用 Tesseract 做光学字符识别并取得词级边框，再由分析器识别实体，最后按边框填充颜色。

可借鉴之处有两项。第一，边框级遮盖而非整图处理，与我们的区域填充思路一致。第二，填充颜色、识别器与阈值均可配置，便于审计与复现。

局限有三项。第一，依赖 Tesseract 系统包与语言数据，镜像体积增加明显。第二，中文实体识别需要额外的语言模型，两周工期内不划算。第三，它只处理文本类信息，不检测人脸与二维码。

结论：作为流程与接口设计参考，不作为依赖引入。我们的文本类信息仍由人工框选。

### 3.2 opencv/opencv_zoo 的 YuNet

YuNet 是轻量人脸检测模型，在 WIDER Face 验证集上的平均精度为 0.834、0.824 与 0.708，分别对应简单、中等与困难子集。模型文件为 227 KB，许可证为 MIT。OpenCV 提供 `cv2.FaceDetectorYN` 接口，直接加载 ONNX 模型，无需 PyTorch。

可借鉴之处有三项。第一，模型体积极小，适合放入离线容器与公开仓库的下载脚本。第二，可在中央处理器上实时运行，符合 NFR-01。第三，官方提供 Python 调用示例，接入成本低。

局限有一项。模型对极小人脸（小于 10 像素）效果有限。本项目场景中，路人面部通常占画面比例较低，仍须人工复核兜底。

结论：作为人脸候选检测的主方案。相较 OpenCV 自带的级联分类器，YuNet 在侧脸、遮挡与低照度条件下更稳定，模型体积仍在可接受范围。

### 3.3 zxing-cpp/zxing-cpp

该项目是 ZXing 的 C++ 实现，提供 Python 绑定。安装方式为 `pip install zxing-cpp`。3.2.0 版本为 Python 3.11 提供 macOS ARM64、Linux AArch64、Linux x86_64 与 Windows 的预编译包。接口返回条码的文本、格式与四边形位置。

可借鉴之处有两项。第一，直接返回四边形位置，可用于生成打码区域。第二，对旋转、倾斜与多码场景的鲁棒性优于 OpenCV 内置检测器。

局限有一项。引入新依赖会增加镜像体积与跨平台验证成本，与两周工期的精简原则冲突。

结论：作为备选。首版使用 OpenCV 内置检测器。若复核中发现倾斜二维码漏检比例较高，再引入该库替换检测器，接口不变。

### 3.4 facebookresearch/EgoBlur

该项目提供命令行工具，检测人脸与车牌后执行模糊，支持图像与视频。工程结构完整，包含模型管理、批量处理与结果可视化。

可借鉴之处有两项。第一，命令行参数设计与批量处理方式可作为参考。第二，其评估思路强调在真实场景中统计漏检，而非只报告模型指标。

局限有两项。第一，依赖 PyTorch 与 Project Aria 工具链，镜像体积与安装复杂度远超本项目需要。第二，模型面向 Aria 设备采集的数据，与手机拍摄的课堂照片分布不同。

结论：仅参考其命令设计与评估思路，不引入依赖。

### 3.5 karant-dev/AutoRedact

该项目是浏览器端图像打码工具，使用 Tesseract.js 取得词级边框，再按邮箱、IP、卡号与密钥等规则定位敏感文本。所有处理在本地完成，支持批量与命令行模式。

可借鉴之处有两项。第一，先取得词级边框再按规则匹配，比整行遮盖更精确。第二，命令行与图形界面共用同一引擎，便于复核。

局限有两项。第一，许可证为 GPL-3.0，不得将其代码复制进本项目。第二，Tesseract.js 运行在浏览器环境，与 Python 技术栈不兼容。

结论：仅参考其规则匹配与边框定位思路，不复制代码。

### 3.6 SYasJ/hushshot

该项目面向屏幕截图与文档，自动遮盖卡号、邮箱、电话、地址、人脸、二维码与条码，并清除元数据。处理全程在浏览器本地完成，提供人工确认环节。

可借鉴之处有两项。第一，功能边界与我们的需求高度接近，可作为验收清单的对照。第二，明确将元数据清除列为独立步骤，与本项目设计一致。

局限有一项。技术栈为前端 JavaScript，无法直接复用。

结论：作为功能清单与交互流程的参考。

### 3.7 noirdoc-ai/mask-engine

该项目面向德语与英语文档，基于 Presidio 做文本脱敏，支持可逆占位符与命名空间管理。其价值在于实体分类与占位符设计。

可借鉴之处有一项。实体类型划分较完整，可作为人工复核时的检查清单，例如姓名、地址、电话、证件号与账户号。

局限有一项。仅处理文本与文档结构，不处理图像像素。

结论：作为复核清单参考，不作为依赖引入。

## 6. 推荐方案

1. 人脸检测采用 YuNet，模型文件纳入下载脚本并校验哈希。OpenCV 自带级联分类器保留为降级路径，当模型缺失或加载失败时启用。
2. 二维码检测首版使用 OpenCV 内置检测器。复核阶段统计漏检比例，若倾斜样本漏检超过 10%，改用 zxing-cpp。
3. 文本类个人信息维持人工框选。不引入 Tesseract 与语言模型，以免增加镜像体积与两周工期的不确定性。
4. 打码方式维持实心填充。presidio 与 hushshot 均支持填充与模糊，本项目选择不可逆方案。
5. 复核与审计参考 hushshot 的功能清单，逐项确认人脸、二维码、文本与元数据四类风险。

## 7. 对现有设计的影响

1. ADR-0006 中的人脸检测器由级联分类器改为 YuNet，降级路径保留级联分类器。该变更单独记录于 ADR-0007。
2. 配置新增检测器选项，默认值为 YuNet。
3. 依赖清单不新增 Python 包。YuNet 通过 OpenCV DNN 加载，仅新增约 227 KB 的模型文件。
4. 环境方案新增模型下载与校验步骤，权重不纳入版本控制。
