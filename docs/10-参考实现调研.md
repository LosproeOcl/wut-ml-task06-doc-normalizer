## 1. 调研目的与方法

本文回答三个问题。

1. 课程要求的四个环节，即文档定位与矫正、去反光与增强、传统机器学习基线、轻量深度学习分类，是否有可直接参考或复用的公开实现。
2. 这些实现的技术路线、依赖成本与许可证是否适合本项目。
3. 哪些项目只能作为相关工作引用，哪些可以进入实现。

检索平台为 GitHub，检索词覆盖 document scanner、document rectification、document dewarping、document shadow removal、document image classification、slide classification 等。筛选标准有四项：能够离线运行；提供图像级处理；许可证明确；技术栈与 Python、OpenCV 兼容。星标数为 2026 年 11 月 26 日检索结果。

## 4. 分技术线分析

### 4.1 文档定位与透视矫正

#### DocAligner

该项目专门预测文档的四个角点，并将文档拉平。模型以 PyTorch 训练、导出为 ONNX，使用 ONNXRuntime 推理，支持中央处理器与图形处理器；通过 PyPI 安装，许可证为 Apache-2.0。

可借鉴之处有三项。第一，四角预测的输入输出定义与本项目 FR-02、FR-03 完全一致，可作为接口参考。第二，ONNX 推理路径与本项目的离线、跨平台约束相符。第三，模型除角点回归外另设分类头，用于判断画面中是否存在文档，可避免对无文档画面强行输出四角，该设计可用于本项目的定位失败分支。

局限有两项。第一，引入该库会增加一个模型依赖与相应权重，超出两周工期的最小实现。第二，其模型面向通用文档，对投影幕布边界与板书边框的适应性未经本项目数据验证。

结论：作为可选增强与对照实验，不进入首版。首版仍用 OpenCV 轮廓法，实现成本低且可解释。

#### OpenCV-Document-Scanner（andrewdcampbell）

该项目是 Python 与 OpenCV 实现，功能包括自动角点检测、透视变换、图像锐化与颜色阈值处理，并带有交互式界面。技术路线与本项目最接近。

可借鉴之处有三项。第一，角点检测后的候选筛选逻辑，包括面积、长宽比与凸性检查。第二，锐化与颜色阈值的处理顺序。第三，交互式确认环节，可作为人工兜底的设计参考。

局限有一项且关键：仓库未声明许可证。按照默认版权规则，不能复制其代码。只能阅读其思路并独立实现。

结论：作为算法流程参考，不复制代码。

#### docscan 与 pyimgscan

docscan 以 pip 包形式提供从照片到扫描件的完整封装，许可证为 MIT。pyimgscan 使用 OpenCV 完成透视矫正与二值化，许可证为 MIT，但依赖锁定在较旧的 OpenCV 4.2。

可借鉴之处有两项。第一，两者都把“找边、排序、变换、增强、输出”拆成独立步骤，与本项目架构一致。第二，pyimgscan 的二值化与反向输出选项，可用于报告中的增强对比图。

局限有两项。第一，功能偏重“扫描件美化”，不包含四角精度评估。第二，pyimgscan 的旧版依赖与本项目 OpenCV 4.10 以上不兼容，不能直接安装。

结论：参考步骤划分与输出形式，不引入依赖。

#### OSS-DocumentScanner

该项目是产品级移动端文档扫描应用，许可证为 MIT。其价值不在算法细节，而在完整的产品流程，包括拍摄、裁剪、人工修正与导出。

可借鉴之处有两项。第一，用户可手动修正四角，与本项目“自动检测加人工兜底”的设计一致。第二，导出前的质量检查环节。

局限有一项。技术栈为移动端应用，与本项目的 Python 处理链路不同，无法复用代码。

结论：作为产品流程与失败兜底设计的参考。

### 4.2 去反光与光照增强

#### DocProj

该项目使用基于图块的卷积网络同时完成几何矫正与光照校正，许可证为 MIT，论文发表于 SIGGRAPH Asia 2019。训练数据由 Blender 合成，包含光流与掩码。

可借鉴之处有两项。第一，论文对“几何畸变”与“光照不均”两类退化的分解方式，可用于本项目的实验设计，即分别报告拉正增益与增强增益。第二，合成数据的构造方法，可作为后续扩展的参考。

局限有三项。第一，模型与训练数据体积大，不适合两周工期。第二，输入输出为任意形变文档，超出本项目“平面四角透视”的范围。第三，合成数据与真实教室照片存在域差距。

结论：仅作相关工作引用，不进入实现。

#### DocShadow 与 illtrtemplate-model

DocShadow 提供高分辨率文档阴影去除的 ONNX 实现，许可证为 MIT，支持 TensorRT。illtrtemplate-model 提供模板引导的光照校正研究代码，许可证为 MIT。

可借鉴之处有一项。两者都把“阴影”与“内容”分离处理，说明单纯全局直方图均衡不足以处理强阴影。

局限有两项。第一，均需额外模型权重与推理框架，超出本项目“OpenCV 增强”的设定。第二，强镜面反光区域的信息已经丢失，任何后处理都无法真正恢复，因此本项目将反光样本作为定位与增强的困难案例，而不是承诺完全消除。

结论：作为增强环节的上界参考，不进入首版。

#### 传统增强

本项目首版采用限制对比度自适应直方图均衡，即 CLAHE，配合自适应阈值去阴影。该方案在 OpenCV 官方文档中有完整说明，无需第三方实现。评估时通过增强开关做消融，量化其增益。

### 4.3 传统机器学习基线

该环节没有与本项目类别体系一致的开源实现。可参考的官方资源如下。

| 资源 | 用途 |
|---|---|
| scikit-image 的方向梯度直方图实现 | 提取局部形状特征 |
| scikit-learn 的支持向量机、随机森林与网格搜索 | 分类器训练与参数选择 |
| OpenCV 的轮廓、矩与直方图函数 | 版面密度与边缘方向特征 |

本项目在此基础上的自有设计是：版面像素密度、边缘方向直方图与方向梯度直方图三组特征拼接，标准化后送入支持向量机与随机森林。该设计记录于 ADR-0002。

结论：使用官方库，不复制第三方项目代码。

### 4.4 轻量深度学习分类

#### pytorch/vision

官方仓库提供 MobileNetV3 的实现与 ImageNet 预训练权重，许可证为 BSD-3-Clause。本项目直接使用其模型定义与权重，不复制训练脚本。

#### slide-classifier

该项目使用 MobileNetV4 对幻灯片、疑似幻灯片与非幻灯片进行分类，许可证为 MIT。其数据存在明显类别不均衡，项目分别提供了基于 PIL 与基于 OpenCV 的两套预处理，以保证跨平台结果一致。

可借鉴之处有三项。第一，类别不均衡的处理方式与本项目纸质、幕布分布不均的情况相似。第二，基于 OpenCV 的预处理路径与 ADR-0004 的跨平台要求一致。第三，小规模数据下的训练组织方式。

局限有两项。第一，类别体系为“是否幻灯片”，与本项目的文字、公式分类不同。第二，项目规模小，工程完整度有限。

结论：参考类别不均衡与预处理一致性做法，不复制代码。

#### 中文文档分类相关项目

LayoutLMv3 中文文档分类项目使用文本与版面信息，适用于 PDF 文本抽取后的分类；本项目输入为照片，无法直接获取文本层，且引入大型预训练模型不符合两周工期与中央处理器约束。PDF 版面分析类项目同理。

结论：不适用，仅在相关工作中说明区别。

### 4.5 评估与可视化

指标计算使用 scikit-learn 的准确率、F1 与混淆矩阵实现；置信区间使用自助法重采样；两模型比较使用麦克尼马尔检验。图表使用 matplotlib 与 seaborn。以上均为官方库或标准统计方法，无需第三方项目。

可视化方面，可参考 docscan 与 OSS-DocumentScanner 的“原图、矫正图、增强图”三联展示方式，以及本项目已定义的六至八张并排图规范。

## 8. 结论与选型建议

1. 第一与第二环节采用 OpenCV 传统方案，理由是任务为平面文档的四角透视，不需要曲面展平模型；传统方案在中央处理器上可实时运行，且每一步可解释、可评估。
2. DocAligner 作为可选对照。若自研定位在合规样本上的自动检出率低于 80%，再引入该库做对比或兜底，接口保持一致。
3. 第三环节使用 scikit-image 与 scikit-learn 的官方实现，特征设计由本项目完成，不复制第三方代码。
4. 第四环节使用 torchvision 的 MobileNetV3 与 ImageNet 权重；类别不均衡处理参考 slide-classifier 的做法，训练与评估仍按本项目方案执行。
5. 去反光以 CLAHE 与去阴影为主。DocProj、DocShadow 等深度方法仅作为相关工作，说明其能力上界与代价，不进入首版。
6. 公开数据集只用于报告中的域差距讨论，不参与训练与评估。
