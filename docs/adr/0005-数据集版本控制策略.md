# ADR-0005：图片文件不纳入版本控制，以清单保证可追溯性

- 状态：已接受
- 日期：2026 年 11 月 25 日
- 决策人：余青阳、李念
- 相关文档：`04-数据采集与标注规范.md`，风险 R-09、R-14

## 背景

本项目计划采集 200 至 320 张手机原始照片。按单张 3 至 6 MB 估算，总量约 0.8 至 1.9 GB。GitHub 对单个文件限制 100 MB，对仓库体积亦有建议上限。若将原图直接纳入版本控制，将出现三类问题：推送被拒绝、克隆耗时过长、历史体积无法回收。

同时，数据须可追溯。报告需要说明每张样本的拍摄者、设备、场景与类别，复现时也需要确定的数据集合。

## 备选方案

| 方案 | 可追溯性 | 仓库体积 | 协作成本 | 结论 |
|---|---|---|---|---|
| 图片直接入库 | 高 | 很大，超出限制 | 克隆缓慢 | 不采用 |
| 图片经 Git LFS 入库 | 高 | 仓库较小，但 LFS 配额有限 | 成员须安装 LFS，配额可能不足 | 不采用 |
| 图片不入库，清单入库 | 中等偏高 | 很小 | 成员各自持有原图，按清单核对 | 采用 |
| 使用外部数据版本工具 | 高 | 很小 | 需额外服务与凭据 | 不采用 |

## 决策

1. 图像二进制文件不纳入版本控制。`.gitignore` 排除 `data/raw_samples/` 与 `data/annotations/` 下的图像文件。
2. 目录结构、占位文件与说明文档纳入版本控制，保证克隆后目录完整。
3. 样本清单 `data/manifests/sample_manifest.csv` 纳入版本控制，作为样本的唯一可信来源。清单记录样本标识、文件路径、类别、分组键、拍摄者、设备、场景、角度、光照、分辨率与拍摄日期。
4. 数据集划分文件 `data/splits/split_v1.json` 纳入版本控制，并记录冻结日期。
5. 样本原图由组员在本地保存，并按清单核对。提交报告前，由数据负责人执行一次完整性核对，确认清单中的每条记录均能找到对应文件。
6. 留证照片体积较小，纳入版本控制，存放于 `docs/assets/`。

## 理由

1. 该方案使仓库体积保持在数 MB 量级，避免推送失败与克隆缓慢。
2. 清单字段足以支撑数据统计、划分复现与报告说明，可追溯性满足课程要求。
3. 不引入 Git LFS 或外部数据版本服务，降低组员环境配置成本，与 ADR-0004 的简化环境策略一致。
4. 若后续需要长期归档原始数据，可另行打包存放于本地或课程平台，不影响仓库结构。

## 后果

1. 评审无法仅通过克隆仓库获得原始图像。报告中须说明数据的获取方式，并附采数留证照片。
2. 复现核验须由持有原始数据的组员执行，或在核验前另行提供数据包。
3. 若后续确需将图像纳入版本控制，须先评估总量是否低于 100 MB，或改为 Git LFS，并补充新的架构决策记录。
4. 清单与实际文件不一致是本方案的主要失效模式，须在 M1 与 M4 各执行一次完整性核对。
