# ADR-0014：标注检查页与退回重标

- 状态：已接受
- 日期：2026 年 11 月 26 日
- 决策人：余青阳、张毅卓、孔泽宇
- 相关文档：`01-需求分析.md` FR-29、`data/annotations/README.md`、`web/README.md`

## 背景

训练集四角已按人分配并保存，但保存不等于合格：自动建议可能只框住局部版面，成员也可能连点四角形成明显偏离的四边形。此前只能直接修改 `manual_corners.csv` 或让成员自行重做，缺少“检查全部成员结果并退回”的入口，也没有保留退回前的坐标与原因。

## 决策

1. 新增 `GET /api/review/corners`，汇总全部训练集四角记录，支持按 `assignee`、`status`（`saved` / `redo` / `unannotated`）、`limit` 与 `offset` 筛选，返回坐标、标注人、状态和退回原因。
2. 新增 `POST /api/review/corners/{sample_id}/redo`，把已保存样本发回重标：
   - 将原坐标、分配成员、原因与时间写入 `data/annotations/redo_corners.csv`；
   - 从 `manual_corners.csv` 删除该条记录，使样本重新进入该成员的待标注队列；
   - 同一 `sample_id` 只保留一条待处理记录。
3. 成员重新提交四角时，`/api/corners` 保存成功后清除对应的退回记录；退回原因在标注页与检查页均可见。
4. 前端新增“标注检查”页：按成员与状态筛选，卡片叠加四角轮廓，逐条“发回重标”；分页浏览，不一次性载入全部图片。
5. 退回只允许训练集样本；验证与测试集保持冻结，不进入任何人工覆盖流程。
6. `redo_corners.csv` 是审计文件，不参与训练；训练仍只读取 `manual_corners.csv` 的有效记录。

## 理由

1. 把“检查”和“重标”串成闭环，避免检查者直接改他人数据，责任仍落在原分配成员。
2. 保留退回前坐标，便于复盘是自动建议偏差还是人工操作偏差。
3. 删除有效记录而不是打标记，训练与统计逻辑无需理解额外状态，减少口径分叉。
4. 分页与筛选让全量 236 张的检查在浏览器中可控，不需要一次加载全部原图。

## 后果

1. 检查者需要与服务端在同一台机器或通过既有反向代理访问；不新增账号体系。
2. 退回后该成员的“已保存四角”计数下降，进度统计以 `redo` 字段单独展示。
3. 若误退，可由该成员重新提交原坐标恢复；`redo_corners.csv` 保留审计痕迹。
4. 后续若需要“退回给其他成员”，应扩展 `assignees.csv` 而不是在退回接口里直接改分配。
