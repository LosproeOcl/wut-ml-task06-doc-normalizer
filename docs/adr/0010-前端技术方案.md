# ADR-0010：前端采用 FastAPI 与原生 JavaScript，不引入构建链

- 状态：已接受
- 日期：2026 年 11 月 26 日
- 决策人：余青阳、孔泽宇、李念
- 相关文档：`01-需求分析.md` FR-19 至 FR-24、`03-架构设计.md` 第 14 节、`05-项目计划与分工.md`

## 背景

课程答辩需要现场演示交互：上传或选择一张斜拍文档，展示四角检测、拉正、增强与分类结果，并在自动检测失败时允许人工调整四角。当前系统只有命令行与脚本，不满足演示需求。

项目约束如下：两周工期；组员设备涵盖 ARM 与 x86；不得依赖外部服务；不得要求组员安装 Node 工具链；前端需要支持鼠标拖拽四个角点并实时重算。

## 备选方案

| 方案 | 开发成本 | 交互能力 | 环境负担 | 结论 |
|---|---|---|---|---|
| Gradio 或 Streamlit | 低 | 中等，角点拖拽与画布叠加受限 | 增加较大依赖 | 不采用 |
| FastAPI 加原生 JavaScript 与 Canvas | 中等 | 完全可控，可拖拽角点 | 依赖小，无 Node | 采用 |
| React 或 Vue 加构建链 | 高 | 完全可控 | 需要 Node、构建产物与版本管理 | 不采用 |
| 桌面图形界面 | 高 | 可控 | 跨平台打包困难 | 不采用 |

## 决策

1. 后端使用 FastAPI，提供 JSON API 与静态文件服务。
2. 前端使用原生 HTML、CSS 与 ES Module JavaScript，Canvas 绘制四角与掩码叠加，不引入打包工具。
3. 单进程部署，默认绑定 `127.0.0.1:54312`，随主容器启动；不使用外部 CDN、字体与遥测。
4. 结果图按会话临时存放，默认 1 小时过期，不写入数据集，不进入版本控制。
5. 交互能力包括：上传或选择样本、四角拖拽、重新矫正、增强开关、模型选择、分类概率与耗时展示。

## 理由

1. 原生 JavaScript 足以实现 Canvas 拖拽与分阶段展示，避免 Node 构建链带来的跨平台问题。
2. FastAPI 与现有 Python 技术栈一致，可直接调用处理链路，不需要额外的模型服务。
3. 依赖仅增加 FastAPI、Uvicorn 与 multipart 解析，镜像体积增加有限。
4. 本地绑定与临时结果机制满足离线与隐私要求。

## 后果

1. 新增 `web/` 目录：`app.py`、`schemas.py`、`static/`。
2. 新增依赖文件 `env/requirements-web.txt`，Dockerfile 增加安装层。
3. 容器运行需映射端口，命令改为 `-p 127.0.0.1:54312:54312`。
4. 新增 API 契约测试；前端采用人工验收清单，不引入浏览器自动化框架。
5. 工期增加约 1.5 人日，安排在 12 月 1 日至 3 日，与模型训练并行。


## 后续修订（2026-11-27）

实现阶段对交互范围做了如下调整，不改变本 ADR 的技术选型：

1. 移除样本库下拉框，改为拍照、相册/文件上传；手机端合并相册与文件入口，电脑端使用文件选择。
2. 增加横向批量队列、逐张切换与校准、区间/离散选择、当前/选中/全部 PDF 导出。
3. 矫正图与扫描件支持点击放大；增强图与模型选择不再作为页面并列控件，模型由后端按验证集表现自动选择，增强保留在离线评估与兼容接口中。
4. 前端仍使用原生 JavaScript、Canvas 与后端静态文件服务，未引入 Node 构建链。
