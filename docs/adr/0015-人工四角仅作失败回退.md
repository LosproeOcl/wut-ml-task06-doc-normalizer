# ADR-0015：训练拉正默认使用自动检测，人工四角仅作失败回退

- 状态：已接受
- 日期：2026 年 11 月 26 日
- 决策人：余青阳、任万东、李念
- 相关文档：`01-需求分析.md` FR-27、FR-28，`06-评估与验收方案.md`，`reports/baseline_classic.md`，`reports/cnn_validation.md`
- 关联：修订 ADR-0012 第 4 条

## 背景

训练集 236 条人工四角已全部完成并通过结构校验。原 ADR-0012 规定训练时优先使用人工四角，但验证与测试仍按部署口径使用自动检测。全量替换训练图后，训练与验证的预处理分布不一致，需要验证这种口径是否真的带来收益。

在 `split_v3` 上固定随机种子、轮数、冻结轮数与增强参数，只改变训练集四角来源：

| 策略 | 传统 SVM | MobileNetV3 |
|---|---:|---:|
| 不使用人工四角 | 76.5% | 74.5% |
| 全部优先使用 | 72.5% | 64.7% |
| 仅自动失败时回退 | 74.5% | **80.4%** |

## 决策

1. `train_classic.py` 与 `train_cnn.py` 的默认策略改为 `--corners-policy fallback`。
2. `fallback` 的执行顺序为：先运行自动检测；检测成功时使用自动四角；检测失败时才使用人工四角。
3. 验证集与测试集永远不使用人工四角，保持与部署一致。
4. 人工四角继续用于网页交互演示、标注审查，以及自动失败样本的兜底；不作为默认的整体训练拉正来源。
5. `always` 与 `none` 保留为实验开关，报告中必须注明所用策略。
6. 传统基线报告显式使用 `none`，因为传统特征上人工四角无显著收益；CNN 正式结果使用 `fallback`。

## 理由

1. 全量使用人工四角会把 236 张训练图全部换成紧贴文档边缘的裁切，验证集却仍是自动检测结果，分布偏移导致 CNN 从 74.5% 降到 64.7%。
2. `fallback` 保留约 196 张自动检测成功的训练图，只对约 40 张失败样本使用人工四角，既修正了检测失败，又没有整体改变训练分布。
3. CNN 在 `fallback` 下达到 80.4% / 79.0%，高于自动基线与传统基线；这是当前最佳验证结果。
4. 验证集只有 51 张，单张影响约 2 个百分点，因此报告同时给出 McNemar 检验，不把点估计差异说成确定结论。

## 后果

1. ADR-0012 第 4 条“训练时优先使用人工四角”由本决策修订为“自动失败时回退”。
2. 训练日志与 `metrics.json` 记录 `corner_policy` 与 `n_manual_corners`，便于复现。
3. 网页演示仍可实时拖拽四角；它不影响离线训练口径。
4. 若后续引入边缘留白、混合训练或 320 像素输入，需要重新评估是否改变默认策略。
5. 测试集保持冻结，最终只评估一次。
