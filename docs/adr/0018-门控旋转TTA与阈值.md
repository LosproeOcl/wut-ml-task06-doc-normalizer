# ADR-0018：网页门控启用旋转 TTA 与 0.3 阈值

- 状态：已接受（待真实偏度样本复核）
- 日期：2026 年 11 月 27 日
- 决策人：余青阳、蒋翔恒、李念
- 相关文档：`docs/15-空间偏度优化调研.md`、`docs/03-架构设计.md`、`reports/web_integration.md`
- 关联：ADR-0017

## 背景

PPT 正面样张识别稳定，但空间偏度样张的完整链路准确率下降。合成偏度压力测试显示：

- 内容模型在 30°/40° 仍有 90.5%/85.7%；
- 载体门控在 40° 的 PPT 召回只有 38.1%，大量 PPT 被分到纸质分支；
- 门控 TTA + 阈值 0.3 把 30°/40° 完整链路从 76.2% 提升到 85.7%，五个角度平均从 86.7% 提升到 89.5%。

## 决策

1. 网页门控默认启用 `web.gate_tta=true`：对原图做 -12°/0°/12° 旋转，平均 `P(ppt)`。
2. 门控默认阈值从 0.5 调整为 `web.gate_threshold=0.3`。
3. 支持环境变量覆盖：`DOCNORM_GATE_TTA=0/1`、`DOCNORM_GATE_THRESHOLD=0.5`；不需要改代码即可回退。
4. TTA/阈值只改变载体分支选择，不改变内容模型、纸质分支或 PPT 分支权重。
5. `/api/health` 的 `routing` 同时报告 `gate_threshold` 与 `gate_tta`，便于演示时核对。
6. 真实偏度样本到位后，按角度分桶复测；若正面样本出现明显回退，再调整阈值或改为条件启用。

## 理由

1. 门控是当前偏度链路的主要瓶颈，内容模型不是。
2. 阈值 0.3 + TTA 在没有新增样本的情况下取得最大收益，且合成测试中纸质召回保持 100%。
3. 门控输入 160×160，三次旋转推理成本低，端到端仍在百毫秒级。
4. 保留环境变量回退，避免阈值调整影响未知的真实纸质分布。

## 后果

1. 网页门控推理约增加 3 倍（门控本身很小，整体耗时增加有限）。
2. 10° 合成偏度下有一张样张从“纸质分支纠错”变为“PPT 分支误判”，属于阈值 trade-off；真实数据到位后需复核。
3. 门控阈值/TTA 不改变训练数据与模型；划分与测试集仍冻结。
4. 需要在 `docs/15`、`docs/03`、`docs/11`、README 与 CHANGELOG 中记录；不新增 GitHub Pages 部署。
5. 若后续引入真实偏度数据并重新训练门控，应重新评估阈值，不直接沿用 0.3。
