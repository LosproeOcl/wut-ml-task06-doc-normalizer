# 投影幕布检测方案

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-26 |
| 目标 | 先定位投影幕布，再裁出幕布做文字/公式分类，缓解 PPT 远景、幕布边界弱、自动四角失败的问题 |
| 外部数据 | SCB-Dataset 教师子集的 `screen` 类框；仅用于屏幕检测器，不进入分类训练/评估 |
| 评估 | 自采 `split_v3` 验证集 51 张；测试集不参与 |

## 1. 数据依据

- `Projection Screen Detection` 论文收集了约 2,093 帧投影幕布数据，但 Data availability 声明“不共享数据”，无法直接下载。
- `SCB-Dataset` 是公开数据（GitHub `Whiffe/SCB-dataset`，HuggingFace `wintonYF/SCB-Dataset`），其教师子集包含 `screen` 类边界框；论文报告 screen 类 mAP@0.5 约 97.9%。
- 本方案使用 SCB5 教师子集（Stand / BlackBoard / Screen）中的 `screen` 框训练轻量屏幕检测器。

## 2. 检测器

- 骨干：MobileNetV3-Small（ImageNet 预训练）。
- 输入：整图缩放到 224×224。
- 输出：归一化 `(cx, cy, w, h)`，转 `xyxy`。
- 损失：SmoothL1 + `1 - IoU`。
- 训练：SCB `screen` 框，默认最多 1,200 张训练图，早停看验证 IoU。
- 产出：`runs/screen-detector-01/screen_detector.pt`、`metrics.json`、`run.json`、`train.log`、`epochs.csv`。

## 3. 与分类管线集成

```text
原图
 ├─ 自动四角检测成功 → 透视拉正 → 分类（基线）
 └─ 自动四角检测失败
      └─ 屏幕检测器预测幕布框
           └─ 外扩 6% 裁剪
                └─ 裁剪图内再做四角检测；成功则拉正，失败则直接用裁剪图
                     └─ 分类
```

只替换“自动四角失败”的分支，避免屏幕检测误差影响已经成功的样本。

## 4. 评估

`scripts/eval_screen_fallback.py` 对自采验证集逐张比较：

- baseline：自动四角，失败保留原图；
- fallback：自动四角失败时用屏幕检测器裁剪；
- 记录准确率、宏 F1、混淆矩阵和发生变化的样本。

结果：`screen-detector-02` 验证 IoU 0.655、IoU@0.5 召回 0.798，但自采 fallback 78.4%，低于 baseline 80.4%；会把纸质公式页误裁剪。当前只保留为诊断工具，需增加屏幕存在性/置信门控后再决定是否进入主链路。

## 5. 边界与风险

1. SCB 是教室行为数据，屏幕框可能包含黑板/投影幕布边缘；检测器学到的更多是“屏幕区域”，不是文字/公式内容。
2. 屏幕框是轴对齐矩形，不解决透视；裁剪后仍需四角检测/拉正。
3. 若屏幕检测器在自采验证集上误检，可能把非屏幕区域裁进来，需以 baseline/fallback 对比决定是否启用。
4. 外部数据只训练检测器，不进入分类训练、验证或测试；报告需披露来源与用途。
5. 测试集保持冻结。
