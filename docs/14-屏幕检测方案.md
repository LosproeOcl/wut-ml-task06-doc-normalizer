# 投影幕布检测方案

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-26（2026-11-27 增补载体门控） |
| 目标 | 先定位投影幕布，再裁出幕布做文字/公式分类，缓解 PPT 远景、幕布边界弱、自动四角失败的问题 |
| 外部数据 | SCB-Dataset 教师子集的 `screen` 类框用于屏幕检测器；外部 A4 数据用于载体门控辅助训练；均不进入自采验证/测试 |
| 评估 | 自采验证集 51 张（v3/v4/v5 为同一批样本）；测试集不参与 |

## 1. 数据依据

- `Projection Screen Detection` 论文收集了约 2,093 帧投影幕布数据，但 Data availability 声明“不共享数据”，无法直接下载。
- `SCB-Dataset` 是公开数据（GitHub `Whiffe/SCB-dataset`，HuggingFace `wintonYF/SCB-Dataset`），其教师子集包含 `screen` 类边界框；论文报告 screen 类 mAP@0.5 约 97.9%。
- 本方案使用 SCB5 教师子集（Stand / BlackBoard / Screen）中的 `screen` 框训练轻量屏幕检测器。

## 2. 检测器

- 骨干：MobileNetV3-Small（ImageNet 预训练）。
- 输入：整图缩放到 224×224。
- 输出：归一化 `(cx, cy, w, h)`，转 `xyxy`。
- 损失：SmoothL1 + `1 - IoU`。
- 训练：SCB `screen` 框，默认最多 1,200 张训练图，早停看验证 IoU。
- 产出：`runs/screen-detector-01/screen_detector.pt`、`metrics.json`、`run.json`、`train.log`、`epochs.csv`。

### 2.1 屏幕存在性门控

仅有 bbox 回归会在纸质页上误检。新增二层门控：

- MobileNetV3-Small 二分类（screen / other），输入整图 160×160；
- 正类：SCB screen 图 + 自采 train 的 `ppt_*`；
- 负类：SCB 无 screen 框图 + 自采 train 的 `paper_*`；
- 自采 val 不参与门控训练；
- 只有门控概率超过阈值时，才在自动四角失败分支使用屏幕框裁剪。

训练清单 `data/manifests/screen_gate.csv`，模型 `runs/screen-gate-01/screen_gate.pt`。

### 2.2 载体门控（PPT/纸质稿，实验性）

屏幕存在性门控解决“是否投影幕布”，载体门控进一步区分“PPT/幕布 vs A4 纸质稿”，用于选择预处理或内容分支：

- 训练清单 `data/manifests/carrier_gate.csv`：SCB screen + 自采 `ppt_*` 为正类；SmartDoc/Tobacco/IAM/IM2LaTeX 与自采 `paper_*` 为负类；自采 val 不参与训练。
- 规模：2,236 训练 / 1,000 外部验证；模型 `runs/carrier-gate-01/screen_gate.pt`（沿用二分类门控结构）。
- 结果：外部验证 100%，自采验证 51 张全对；外部验证与训练同源，难度偏低，不能直接外推。
- 门控已接入网页主链路；纸质分支使用 `paper-cnn-extctl-01/43/44` 集成，自采纸质验证 80.00%。训练集审计 336/338，错误样本可通过结果卡手动重试。
- 详见 `reports/carrier_routing.md` 与 ADR-0016。

## 3. 与分类管线集成

```text
原图
 ├─ 自动四角检测成功 → 透视拉正 → 分类（基线）
 └─ 自动四角检测失败
      └─ 屏幕存在性门控：P(screen) ≥ 阈值？
           ├─ 否 → 保留原图（基线）
           └─ 是 → 屏幕检测器预测幕布框
                └─ 外扩 6% 裁剪
                     └─ 裁剪图内再做四角检测；成功则拉正，失败则直接用裁剪图
                          └─ 分类
```

只替换“自动四角失败”的分支，避免屏幕检测误差影响已经成功的样本。

## 4. 评估

`scripts/eval_screen_fallback.py` 对自采验证集逐张比较：

- baseline：自动四角，失败保留原图；
- fallback：自动四角失败时用屏幕检测器裁剪；
- 记录准确率、宏 F1、混淆矩阵和发生变化的样本。

结果：

- `screen-detector-02` 验证 IoU 0.655、IoU@0.5 召回 0.798，但无门控时自采 fallback 78.4%，低于 baseline 80.4%，会误裁纸质公式页。
- 加入 `screen-gate-01`（SCB 验证准确率 91.3%）后，阈值 0.2–0.9 下 fallback 均为 **82.35%**，只修复 `IMG_6206`，无新增错误；比 baseline 多对 1 张。
- 当前仍作为可选分支，不默认进入主链路；若要上线，需要更稳定的屏幕存在性门控与更大验证集。

## 5. 边界与风险

1. SCB 是教室行为数据，屏幕框可能包含黑板/投影幕布边缘；检测器学到的更多是“屏幕区域”，不是文字/公式内容。
2. 屏幕框是轴对齐矩形，不解决透视；裁剪后仍需四角检测/拉正。
3. 若屏幕检测器在自采验证集上误检，可能把非屏幕区域裁进来，需以 baseline/fallback 对比决定是否启用。
4. 外部数据可用于屏幕检测器、载体门控与纸质稿辅助训练，但只进入训练集；不得进入自采验证/测试，报告需披露来源与用途。
5. 测试集保持冻结。
