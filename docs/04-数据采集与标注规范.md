# 数据采集与标注规范

| 项目 | 内容 |
|---|---|
| 文档编号 | T06-DATA-001 |
| 版本 | v1.0 |
| 适用范围 | 全体 8 名组员 |
| 数据目标 | 合规样本不少于 240 张，可上浮至 400 张；内容两类均衡，纸质与板书设下限，全程可追溯 |

本规范用于在采集阶段控制数据质量。经验表明，采集完成后才发现样本不可用，其返工成本远高于采集前的一次评审。因此，全部组员须在正式拍摄前阅读本规范，并在归档前逐项完成质量检查。

## 1. 采集配额

评估口径为内容二分类（文字/公式），配额以内容均衡为第一约束；载体不设均衡要求，但纸质与板书设下限。现有样本以投影幕布为主，补采优先投向纸质与板书。

| 类别代码 | 载体 | 内容 | 目标数量 | 说明 |
|---|---|---|---|---|
| `ppt_text` | 投影幕布 | 纯文字 | 约 90 | 现有样本为主 |
| `ppt_formula` | 投影幕布 | 含数学公式或推导 | 约 90 | 现有样本为主 |
| `paper_text` | 纸质笔记或板书 | 纯文字 | 不少于 30 | 优先补采 |
| `paper_formula` | 纸质笔记或板书 | 含公式或推导 | 不少于 30 | 优先补采 |
| 合计 |  |  | 240 | 人均约 30 |

内容两类各占总量 40% 至 60%，任一类不少于 80 张；纸质与板书合计不少于总量 25%。若进度允许，总量可上浮至 400 张，增量优先投向纸质与板书。带有明显反光或亮斑的样本应不少于 30 张，用于验证去反光模块。此类样本不应因画面不美观而重拍。

## 2. 拍摄要求

### 2.1 设备与参数

| 项目 | 要求 |
|---|---|
| 设备 | 手机主摄。关闭人像模式、自动滤镜与美颜功能 |
| 格式 | JPG。不提交 HEIC 格式，不提交屏幕截图 |
| 分辨率 | 不低于 1920×1080，建议采用 4 比 3 原生比例 |
| 对焦 | 点击文档区域完成对焦，确保文字边缘锐利 |
| 闪光灯 | 关闭 |
| 水印 | 关闭。时间水印会污染画面 |

### 2.2 构图

1. 四个角点必须完整出现在画面内，且距画面边界不少于画面短边的 3%。该条件是可自动矫正的前提。
2. 倾斜角控制在 15 度至 60 度之间，其中大于 40 度的样本不少于 30%。
3. 允许画面出现桌椅、讲台与墙面等合理背景，但不得有其他纸张或屏幕抢占主体位置。
4. 一张照片只拍摄一个文档页，不制作拼图，不将多页置于同一画面。
5. 竖版与横版文档均须采集，各自不少于 30%。

### 2.3 光照覆盖

| 光照条件 | 目标占比 | 典型场景 |
|---|---|---|
| 自然光 | 40% | 靠窗教室、白天走廊 |
| 教室顶灯 | 30% | 空闲教室、晚间 |
| 侧向光源 | 20% | 宿舍桌面，台灯或窗外侧光 |
| 逆光或强反光 | 不少于 10% | 幕布高光、窗户在纸面形成亮斑 |

出现明显反光或亮斑的样本，无论主光照条件如何，`lighting` 一律登记为 `backlight`。该口径用于保证反光样本数量可统计。

### 2.4 内容合规

1. 不得拍摄路人正脸、姓名、学号、联系方式、聊天记录与成绩信息。隐私实验所需样本的例外口径见 OQ-09，未形成结论前不得据此采集。
2. 板书与笔记内容可为课程知识，但不得包含个人信息。
3. 无法避开时，入库前须按第 10 节流程打码，并在样本清单中记录隐私字段。
4. 不得使用社交软件自带的马赛克工具。此类工具处理强度不足，且会在传输过程中压缩图像。
5. 不得在上课期间拍摄，以免干扰教学秩序。

### 2.5 留证材料

每位组员提交一张拍摄现场照片，内容可为同伴持手机拍摄幕布的背影或侧影，不出现正脸。文件命名为 `onsite_<姓名缩写>.jpg`，存放于 `docs/assets/`。该文件须纳入版本控制。

## 3. 类别判定规则

为避免边界样本判定不一致，按下述顺序判定。

第一步判定内容属性。页面是否出现数学符号、公式或推导过程，包括等号、积分号、求和号、上下标、矩阵与分数。若此类符号占版面面积不少于 5%，判定为公式类。仅出现个别行内符号，例如“准确率不低于 85%”，仍判定为文字类。

第二步判定载体属性。投影幕布或电子屏具有边框、亮度较高，常带模板色块，判定为幕布类。白纸、横线本、黑板与白板判定为纸质或板书类。

第三步处理存疑样本。无法明确判定的样本放入 `99_unlabeled/` 目录，在组内说明理由，由数据负责人裁定。不得自行猜测后直接入库。

## 4. 文件命名与目录结构

### 4.1 命名规则

```text
T06_P<组员编号>_<类别>_<场景>_<序号>.jpg
```

示例：

```text
T06_P03_pptFormula_classroom_017.jpg
T06_P07_paperText_dorm_004.jpg
```

| 字段 | 取值 |
|---|---|
| 组员编号 | P01 至 P08，与分工表一致 |
| 类别 | `pptText`、`pptFormula`、`paperText`、`paperFormula` |
| 场景 | `classroom`、`corridor`、`dorm`、`outdoor` |
| 序号 | 每位组员每类三位递增，从 001 开始 |

样本标识取文件名去掉扩展名，须全局唯一。文件入库后不得改名。确需改名时，须同步更新样本清单并说明原因。

### 4.2 目录结构

```text
data/raw_samples/
├── 00_inbox/          原始导入，尚未整理
├── 01_ppt_text/       投影幕布，纯文字
├── 02_ppt_formula/    投影幕布，含公式
├── 03_paper_text/     纸质或板书，纯文字
├── 04_paper_formula/  纸质或板书，含公式
└── 99_unlabeled/      类别存疑，待裁定
```

图像文件由 `.gitignore` 排除，版本控制中仅保留目录、占位文件与说明文档。

## 5. 样本清单登记

每张图像对应清单中的一行。清单文件为 `data/manifests/sample_manifest.csv`，示例行如下。

```csv
sample_id,file,label,doc_page_id,shooter,device,scene,angle_deg,lighting,resolution,shot_at,notes,privacy_masked,privacy_regions,release_file
T06_P03_pptFormula_classroom_017,02_ppt_formula/T06_P03_pptFormula_classroom_017.jpg,ppt_formula,PPT-CALC-03,yqy,iPhone 14,classroom,35,ceiling,4032x3024,2026-11-27,幕布右侧高光,true,1,release/02_ppt_formula/T06_P03_pptFormula_classroom_017.jpg
```

字段定义见 `03-架构设计.md` 第 6.1 节。

其中 `doc_page_id` 须特别说明。同一张幻灯片由不同组员从不同角度拍摄时，这些样本必须登记相同的 `doc_page_id`。若该字段填写错误，同一文档页的样本会同时进入训练集与测试集，导致指标虚高。建议命名格式为“载体-主题-序号”，例如 `PPT-CALC-03`、`PAPER-LINALG-07`。

## 6. 数据集划分

1. 以 `doc_page_id` 为分组键，按 70%、15%、15% 的比例划分为训练集、验证集与测试集。
2. 划分时按内容类别与拍摄者分层，使各集合分布接近；载体分布作为检查项，不强制均衡。
3. 测试集须包含至少两名非主要拍摄者的样本，用于检验设备与拍摄习惯的泛化能力。
4. 划分文件 `data/splits/split_v1.json` 在 M1 结束时冻结，此后不得修改。
5. 后续补充采集的样本只能加入训练集。若确需重建划分，须生成 `split_v2.json` 并重跑全部实验，不得在报告中混用两个版本的结果。
6. 打码区域覆盖文档主体超过 5% 的样本不进入测试集，以免展示图与评估图不一致。

## 7. 质量检查清单

归档前逐项确认。

- 四个角点完整，且距画面边界不少于 3%。
- 文字与公式在原始分辨率下可辨认。
- 无大面积过曝，无严重欠曝。
- 无时间水印、无手机界面元素。
- 无个人信息，包括人脸、姓名与学号。
- 类别判定符合第 3 节规则。
- 文件名符合规则，样本标识唯一。
- 已在样本清单中登记，`doc_page_id` 正确。
- 非屏幕截图，非经即时通讯软件转发的图像。
- 同一文档页的拍摄角度不超过 6 个。
- 已执行隐私候选检测，并完成人工复核。
- 对外使用的副本不含可识别人脸、二维码、姓名与学号。

## 8. 常见返工原因

| 现象 | 后果 | 预防措施 |
|---|---|---|
| 角点被画面裁切 | 无法矫正，样本作废 | 拍摄后立即检查画面边缘 |
| 经即时通讯软件传图 | 图像被压缩，文字模糊，元数据丢失 | 使用数据线、隔空投送或局域网传输 |
| 同一文档页的样本分属不同集合 | 指标虚高 5 至 15 个百分点 | 强制登记分组键，划分脚本校验 |
| 全部为正拍，缺少倾斜样本 | 矫正模块缺少可评估样本 | 按角度配额拍摄 |
| 公式页均为远景 | 类间差异退化 | 约束最小字号与拍摄距离 |
| 仅使用一台设备 | 泛化能力不足 | 覆盖至少四种机型 |
| 直接用原图制作报告配图 | 泄露个人信息 | 只使用 `data/release/` 中的打码副本 |

## 9. 标注需求

本课题不要求像素级多边形标注。所需标注如下。

| 标注类型 | 用途 | 工具 | 优先级 |
|---|---|---|---|
| 图像级类别 | 分类监督 | 样本清单 | 必须 |
| 四角坐标 | 矫正精度评测基准 | 标注脚本与 JSON 文件 | 应当 |
| 文档页分组 | 防止数据泄漏 | 样本清单的 `doc_page_id` 字段 | 必须 |
| 隐私区域 | 打码与复核 | `privacy` 命令与区域文件 | 必须 |

四角坐标标注文件为 `data/annotations/corners.json`，格式如下。

```json
{"T06_P01_pptText_classroom_001": [[x1, y1], [x2, y2], [x3, y3], [x4, y4]]}
```

坐标顺序固定为左上、右上、右下、左下。建议标注 40 张，覆盖四格归档类别与不同倾斜角，并兼顾纸质与板书样本。

## 10. 隐私打码流程（取消，D-01）

自动打码能力按决定 D-01 取消开发（非课程要求）；数据清洗已完成：含个人信息样本经 `data/manifests/exclusions.csv` 排除出数据集与对外使用。本节流程仅作历史存档。

本节规定图像在离开本地环境前的处理步骤。适用于报告配图、演示文稿、公开仓库与任何对外提交的材料。

### 10.1 处理对象

| 对象 | 说明 |
|---|---|
| 人脸 | 画面中偶然出现的路人、同学与教师面部 |
| 二维码与条形码 | 墙面、桌面、通知与设备上可能指向个人账号的编码 |
| 文本类信息 | 姓名、学号、手机号、聊天记录与成绩信息 |

人脸与二维码由程序生成候选区域。文本类信息由复核人手动框选，程序不负责自动识别。

### 10.2 操作步骤

1. 执行候选检测，生成区域文件与预览图。

```bash
docnorm privacy scan --input data/raw_samples/01_ppt_text --out reports/privacy
```

2. 复核人逐张检查，增删区域。确认后的区域文件锁定，不再由程序修改。
3. 执行打码，输出发布副本。

```bash
docnorm privacy apply --input data/raw_samples/01_ppt_text \
  --regions reports/privacy/regions.json --out data/release/01_ppt_text
```

4. 执行审计，核对发布集合与清单是否一致。

```bash
docnorm privacy audit --input data/release --report reports/privacy_audit.csv
```

### 10.3 处理规则

1. 打码方式默认为实心填充。允许像素化，但不得使用高斯模糊。
2. 打码区域须向外扩展，扩展比例取区域短边的 15%，防止边缘残留。
3. 打码前须去除图像元数据，包括设备型号、拍摄时间与地理位置。
4. 原始样本不得被覆盖。发布副本写入 `data/release/`，目录结构与样本目录一致。
5. 打码区域覆盖文档主体超过 5% 时，该样本不得进入测试集，并在清单备注中注明。
6. 发布副本仅用于对外展示与报告配图，不得作为训练或评估输入。训练与评估使用本地原始样本。

### 10.4 复核要求

复核由非拍摄者执行，逐张确认。复核记录写入 `reports/privacy_audit.csv`，字段包括样本标识、区域数量、打码方式、复核人、复核时间与是否通过。

不通过的情形包括：仍可辨认人脸、二维码可被扫描、姓名或学号可读、打码边缘残留可辨识特征。不通过的样本须重新框选并再次复核。

### 10.5 目录约定

```text
data/release/
├── 01_ppt_text/
├── 02_ppt_formula/
├── 03_paper_text/
└── 04_paper_formula/
```

发布目录中的图像同样不纳入版本控制，仅保留目录说明。
