## 1. 目的与范围

本文规定系统应当具备的功能、性能与数据条件，作为设计、实现、测试与验收的共同依据。

系统接收斜拍文档照片，输出矫正增强图与内容类别。系统不承担光学字符识别与公式语义解析职责。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 斜拍 | 相机光轴与文档平面不垂直，文档在画面中呈梯形的拍摄方式 |
| 矫正 | 定位文档四角并执行透视变换，得到正面矩形图像的过程 |
| 内容类 | 页面的语义属性，取值为文字类或公式类 |
| 载体 | 页面的物理来源，取值为投影幕布或纸质与板书 |
| 文档页 | 同一张幻灯片、同一块板书或同一页笔记的逻辑单位 |
| 分组键 | 用于划分数据集的字段。同一文档页的全部拍摄角度共享同一个分组键 |
| 合规样本 | 文档四角完整可见、无严重遮挡、内容可辨认的样本 |
| 分组划分 | 同一文档页的全部样本只能落入训练集、验证集、测试集三者之一 |

## 3. 用户角色

| 角色 | 说明 | 主要诉求 |
|---|---|---|
| 采集者 | 承担拍摄与登记任务的组员 | 规则简明，一次拍摄合格，避免返工 |
| 分析者 | 执行训练与评估的组员 | 单条命令复现，结果可比 |
| 汇报者 | 制作图表与报告的组员 | 图表可直接引用，错误案例可解释 |
| 评审者 | 任课教师与答辩评委 | 指标真实，对比充分，数据来源可追溯 |

## 4. 用例

### 4.1 用例 UC-01：采集与登记

前置条件：采集者已获得拍摄任务与配额。

主流程：按采集规范拍摄，将原始文件放入 `00_inbox` 目录，判定类别并归档，在样本清单中登记，最后按质检清单自查。

异常流程：四角缺失或图像模糊时重新拍摄，该文件不纳入数据集。

后置条件：样本在清单中具备唯一标识，且拍摄者、设备、场景与角度信息完整。

### 4.2 用例 UC-02：单图矫正

前置条件：输入图像格式合法且可读取。

主流程：检测文档四边形，排序四个顶点，执行透视变换，执行去反光增强，输出正面图与四角叠加图。

异常流程：未检出有效四边形时，返回失败状态与原因，保留原图，不得输出错误结果。

后置条件：输出矫正图及元数据，元数据包含角点坐标、处理耗时与状态标记。

### 4.3 用例 UC-03：批量归类

前置条件：输入目录中的图像已完成归档与登记。

主流程：逐图执行矫正与推理，汇总类别与置信度，生成预测结果文件。

异常流程：单张图像处理失败时不中断批处理，失败样本单独列出。

后置条件：生成预测结果文件与汇总统计。

### 4.4 用例 UC-04：出图与报告

前置条件：已完成模型评估并确定最终模型。

主流程：按指定样本清单生成并排对比图，图中包含原图与四角标注、矫正结果、增强结果与类别标签。

后置条件：生成可直接嵌入报告的图像文件与图注文本。

### 4.5 用例 UC-05：隐私打码与复核（取消，D-01）

自动打码能力为本组自设扩展功能，按 D-01 取消开发；数据清洗（敏感样本排除）已完成，见 `09-风险登记与开放问题.md` 决定 D-01。

前置条件：样本已完成归档与登记。

主流程：执行候选检测，生成人脸与二维码候选区域；由复核人增删区域并确认；执行打码，输出发布副本；记录复核人与处理时间。

异常流程：检测未发现候选但复核人发现个人信息时，手动补框；打码区域覆盖文档主体超过 5% 时，该样本标记为不进入测试集。

后置条件：发布副本不含可识别个人信息，原始样本保持不变，复核记录写入审计文件。

### 4.6 用例 UC-06：网页交互演示

前置条件：本机服务已启动，浏览器访问 `127.0.0.1:8000`。

主流程：上传图片或选择样本；系统展示原图与检测四角；用户可拖拽角点后重新计算；切换矫正与增强开关；查看矫正图、增强图、类别概率与耗时。

异常流程：检测失败时提示可在原图上手动放置四角；上传格式非法时返回明确错误，不进入处理链路。

后置条件：结果仅在当前会话临时保存，默认一小时过期，不写入数据集。

## 5. 功能需求

优先级分为三级：必须、应当、可选。

| 编号 | 需求描述 | 优先级 | 验收条件 |
|---|---|---|---|
| FR-01 | 读取 JPG、JPEG 与 PNG 格式，兼容中文路径与含空格路径 | 必须 | 在 Windows 与 macOS 各完成一次读取测试 |
| FR-02 | 自动检测文档四边形并输出四个顶点的坐标 | 必须 | 合规样本自动检出率不低于 80%；未检出样本在交互界面调整四角或跳过，不设离线标注 |
| FR-03 | 顶点顺序稳定，依次为左上、右上、右下、左下，支持任意旋转方向 | 必须 | 横拍、竖拍与倒置样本各五张全部排序正确 |
| FR-04 | 执行透视变换并输出正面矩形图，输出尺寸可配置 | 必须 | 输出图无明显梯形畸变，长宽比与原始文档相差不超过 10% |
| FR-05 | 提供去反光与对比度增强功能，可独立开关 | 必须 | 同一模型下可完成增强前后的指标对比 |
| FR-06 | 完成内容二分类，类别为文字与公式；采集归档保留载体与内容四格标签，评估时映射为内容二分类 | 必须 | 测试集准确率不低于 85% |
| FR-07 | 输出各类别概率与置信度，并可标记低置信度样本 | 应当 | 置信度低于阈值时写入待复核清单 |
| FR-08 | 传统机器学习基线可独立训练与评估 | 必须 | 单条命令产出指标与混淆矩阵 |
| FR-09 | 轻量卷积神经网络可训练、可评估、可导出权重 | 必须 | 训练日志、最优权重与指标文件齐全 |
| FR-10 | 支持拉正前后、传统方法与深度学习方法的对照实验复跑 | 必须 | 产出统一格式的对比表 |
| FR-11 | 提供批量推理命令行工具，支持目录输入与失败隔离 | 应当 | 单图失败不影响其余样本处理 |
| FR-12 | 生成六至八张并排可视化图组 | 必须 | 图中包含四角标注、类别与置信度 |
| FR-13 | 生成数据统计图，包括类别分布、角度分布与分辨率分布 | 应当 | 可用于报告与数据合规说明 |
| FR-14 | 全部随机过程可固定随机种子 | 必须 | 两次运行的指标差异不超过 0.5 个百分点 |
| FR-15 | 输出错误案例清单及对应图像路径 | 应当 | 至少覆盖三类错误原因 |
| FR-16 | 检测图像中的人脸与二维码，生成隐私候选区域 | 取消（D-01，自设扩展功能） | 在 40 张复核样本上可生成候选区域，输出坐标与预览图 |
| FR-17 | 支持人工增删候选区域并确认打码范围 | 取消（D-01，自设扩展功能） | 区域文件可编辑、可追溯，确认后不可被自动覆盖 |
| FR-18 | 按确认区域生成打码副本，去除图像元数据 | 取消（D-01，自设扩展功能） | 实心填充不可逆；输出副本不包含设备、时间与地理位置信息 |
| FR-19 | 提供本机网页界面，支持上传图片或从样本库选择 | 必须 | 浏览器可完成上传与选择，单文件不超过 15 MB |
| FR-20 | 展示原图、四角标注、矫正图、增强图与分类结果 | 必须 | 五个视图均可切换或并排查看，加载失败有明确提示 |
| FR-21 | 支持拖拽四个角点并重新执行矫正与后续环节 | 必须 | 拖动后在 2 秒内更新矫正图，角点顺序自动校正 |
| FR-22 | 提供矫正开关、增强开关与模型选择 | 应当 | 开关状态影响结果，界面显示当前配置 |
| FR-23 | 显示类别概率、处理耗时与检测方式 | 应当 | 结果面板包含概率条、耗时与 edge/mask 方法标记 |
| FR-24 | 提供示例样本快速载入与结果图下载 | 可选 | 可一键载入测试样本并下载当前阶段图像 |

## 6. 非功能需求

| 编号 | 类别 | 需求描述 | 验证方式 |
|---|---|---|---|
| NFR-01 | 性能 | 中央处理器单图端到端耗时不超过 1.0 秒，图像长边按 1280 像素计 | 容器内基准脚本计时 |
| NFR-02 | 可移植 | 在 linux/amd64 与 linux/arm64 容器中均可运行 | 两种架构各执行一次冒烟测试 |
| NFR-03 | 可复现 | 固定依赖版本、随机种子与线程数，评估统一在中央处理器上执行 | 两名组员独立复跑并比对结果 |
| NFR-04 | 可维护 | 模块之间通过数据契约通信，单个模块可独立替换 | 代码评审检查 |
| NFR-05 | 健壮性 | 非法输入与损坏图像给出明确错误信息，不导致程序崩溃 | 异常用例测试 |
| NFR-06 | 可观测 | 关键步骤记录日志，包含耗时、检出状态与置信度 | 日志抽查 |
| NFR-07 | 隐私 | 不采集、不上传含个人信息的图像，运行时不依赖外部网络服务 | 数据审计 |
| NFR-08 | 资源 | 训练峰值内存不超过 8 GB | 训练过程监控 |
| NFR-09 | 体积 | 单个文件不超过 100 MB，仓库总量不超过 200 MB | 推送前检查 |
| NFR-10 | 隐私 | 对外使用的图像不含可识别个人信息：数据清洗已完成，敏感样本经排除表剔除；处理全程离线 | 排除表与抽查 |
| NFR-11 | 部署 | 网页默认仅绑定 127.0.0.1，不对外网开放；不上传任何图像至外部服务 | 启动日志与网络检查 |
| NFR-12 | 构建 | 前端不引入 Node 构建链，静态文件由后端直接提供 | 干净环境启动验证 |
| NFR-13 | 响应 | 1280 像素长边、传统基线模型下，上传到结果展示不超过 3 秒 | 浏览器计时与接口日志 |

## 7. 数据需求

| 编号 | 需求 | 量化口径 |
|---|---|---|
| DR-01 | 自采样本总量 | 手册要求 200 至 320 张。两周工期下目标 240 张；本组实拍上限 400 张。当前合格 344 张，超出 320 上限 24 张，见 OQ-11；超上限增量须经任课教师认可 |
| DR-02 | 人均配额 | 8 人各 30 张，允许上下浮动 3 张 |
| DR-03 | 内容类别均衡 | 文字与公式两类各占 40% 至 60%，任一类不少于 80 张 |
| DR-04 | 载体覆盖 | 现有样本以投影幕布为主；纸质与板书合计不少于总量 25%，不足时优先补采 |
| DR-05 | 角度覆盖 | 倾斜角 15 度至 60 度，其中大于 40 度的样本不少于 30% |
| DR-06 | 光照覆盖 | 覆盖自然光、教室顶灯、侧向光源与逆光，含明显反光的样本不少于 30 张 |
| DR-07 | 设备覆盖 | 至少四种手机型号，分辨率不低于 1920×1080 |
| DR-08 | 合规性 | 四角完整，无路人正脸，无真实姓名与学号 |
| DR-09 | 分组 | 同一文档页的全部拍摄角度只进入一个数据集合 |
| DR-10 | 可追溯 | 每张图像在清单中具有唯一标识与拍摄者信息 |
| DR-11 | 留证 | 提交一至两张实地采数过程照片，存放于 `docs/assets/` |
| DR-12 | 隐私标记 | 清单记录是否打码、区域数量与发布副本路径 |
| DR-13 | 发布副本 | 对外使用的图像须为打码后的发布副本，且有复核记录 |

## 8. 输出规格

| 产物 | 格式 | 关键字段 |
|---|---|---|
| 矫正图 | PNG 或 JPG | 建议长边 1600 像素，同时保留原图副本 |
| 四角叠加图 | PNG | 四点构成的多边形与顶点编号 |
| 预测结果 | CSV | 样本标识、真实类别、预测类别、各类概率、是否正确、是否低置信度、是否自动矫正、处理耗时 |
| 指标汇总 | CSV 与 JSON | 准确率、宏平均 F1、各类召回率、混淆矩阵 |
| 对比表 | CSV 与 Markdown | 实验编号、配置、准确率、宏平均 F1、备注 |
| 可视化图组 | PNG | 二至四幅并排图与图注 |
| 隐私审计表 | CSV | 样本标识、区域数量、打码方式、复核人、复核时间、是否通过 |

## 9. 范围外需求

以下内容明确不在本项目范围内。

1. 光学字符识别、公式识别与版面还原。
2. 视频流实时处理。
3. 移动端、多用户与公网部署。本机单用户网页演示在范围内。
4. 曲面书页展开、严重遮挡修复与运动模糊复原。
5. 通用匿名化服务。本项目的打码仅服务于自有数据集的对外使用。
6. 文本类个人信息的自动识别。此类信息由人工复核时框选，不由程序判定。

## 11. 需求变更规则

1. 新增或修改需求须提交仓库议题，注明受影响的需求编号与实验编号。
2. 影响指标口径的变更须同步修订 `06-评估与验收方案.md`。
3. 影响系统结构的变更须新增架构决策记录。
4. 项目进入 M3 后仅接受缺陷修正，不接受范围扩张。
